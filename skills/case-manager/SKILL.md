# 案件管家（case-manager）· 单体 Hub

> **设计哲学**：最小干预、自动沉淀——在日常办案交互中，台账随工作推进而自动更新，用户无需刻意"维护台账"。仅预设通用、必要的流程环节，将个性化场景分支留给用户按需定制。
> **平台无关**：所有表格/日程/文档交互通过能力槽调用，用户在 `profile.md` 中绑定实际 provider。无连接器时零依赖本地运行 `[本地模式-协作平台未连接]`。

## 0 | 前置与全局协议

### 0.1 加载画像

读取 `profile.md`，提取：角色（律师/法务）、团队信息、台账绑定、协作偏好、风险校准。

### 0.2 数据源（单台账）

案件管家采用单台账模式，用户可读可写：

| 台账 | profile.md 字段 | 权限 | 触发场景 |
|------|-----------|------|---------|
| **案件台账** | `ledger.<sheet_id>` | **✏️ 读写** | ① 建档 ② 跟进 ③ 阶段流转 ④ 期限 ⑤ 结案 |

> **台账规则**：
> - 收案时先在台账中搜索判断是否已有记录，避免重复建档。
> - 所有操作直接读写台账。

台账后端通过 `COLLAB.sheet_*` 能力槽调用（钉钉 AI 表格 / 飞书多维表格 / 本地 CSV+Sqlite / 自建后端）。字段命名规范由用户在 `profile.md` 的 `ledger_fields` 中声明，本 skill 只引用**语义字段名**（进展/下一步/状态/案件类型/开庭日期等），不硬编码底层列 ID。

### 0.3 通知与提醒

> 期限提醒与案件通知通过最轻量方式触达用户，不预设重度推送体系。

- **默认**：在对话中直接展示临期待办与案件异常。
- **可选增强**：如用户在 `profile.md` 中配置了日历集成（`COLLAB.calendar_*`），关键期限同步写入日历日程；如配置了 IM 推送渠道，临期提醒可经该渠道推送。
- **克制原则**：不主动创建日程或频繁推送——除非用户在冷启动中明确启用。

### 0.4 「下一步三选一」协议

每个业务环节完成后，**必须**输出以下格式：

```
### 下一步建议（三选一）

| 选项 | 内容 | 责任人 |
|------|------|--------|
| **A** ✅ | [AI 可自动完成的下一步动作描述] | AI 默认认领 |
| B | [需要用户人工完成的事项 + 必要的输入提示] | 用户手动 |
| C | 跳过/暂缓本环节 | — |

> 默认执行 A。如需 B/C 请回复 "B" 或 "C"，或直接给出新指令。
```

**AI 默认即时执行 A**，无需等待用户回复。用户随时可以打断、改选 B/C 或下新指令。

### 0.5 子模式分发

根据触发词识别意图，进入本 SKILL.md 对应模块：

| 用户意图 | 触发词 | 分发到 |
|---------|--------|--------|
| 收案录案 | 收案、新案件、录案 | §1 收案 |
| 管辖异议 | 管辖异议、管异 | §2 流程推进（管辖） |
| 还原事实 | 还原事实、调查事实、事实梳理 | §2 流程推进（事实） |
| 制定策略 | 策略、要件、攻防 | §2 流程推进（策略）→ /element-analysis |
| 证据调取 | 证据、组证、公证 | §2 流程推进（证据） |
| 文书撰写 | 文书、答辩、起诉、代理词、质证、上诉 | §2 流程推进（文书） |
| 主诉立案 | 立案、提交立案 | §2 流程推进（立案） |
| 开庭 | 开庭、庭审提纲、庭审 | §2 流程推进（开庭）→ /trial-outline |
| 判决履行 | 判决、履行、执行 | §2 流程推进（履行）|
| 台账查询/全景 | 全景、组合、在办、查台账、建档、更新台账 | §3 台账 |

| 期限 | 期限、待办、提醒、计算期限 | §4 期限 |

无参数 → 询问意图。

### 0.6 定制边界

> **设计原则**：本 Hub 仅预设通用、必要的流程环节（§2 的 9 环节），不提前预设面面俱到的个性化场景。

- **不预设**：委外律师询价选聘、用印审批、庭后客户运营、判决履行缴费等属于特定角色/组织个性化的环节，本 Hub 不内置。
- **可扩展**：用户可通过 `/customize` 在 `profile.md` 中声明自定义流程分支与触发词，Hub 按声明路由。
- **只串套件内技能**：仅衔接本套件内置的子技能（见 §5 衔接列表）；套件外的技能不引用、不预设。

### 0.7 跨技能台账自动回写协议

> **核心原则**：套件内任何技能产出案件级交付物后，**必须**在输出前自动调用台账回写，无需用户手动触发。

**协议单一权威源**：`references/downstream-writeback-protocol.md`（六步流程 / 降级 / 不阻塞规则完整版）。

下游技能通过尾部「案件管家联动（强制）」小节的一行引用触达本协议，禁止复制粘贴协议本体。回写失败不阻塞输出，但必须在末尾标注 `⚠️ 台账未自动更新，请手动记录`。

## 1 | 收案

收案入口：用户口头/文字描述新案件，或从法院送达文书/邮件/短信中提取。

### 1.1 收案五步

1. **信息提取**：从用户输入或送达材料中提取——案由、原告、被告、法院、案号、诉求金额、送达日期、关键期限。
2. **查重**：`COLLAB.sheet_search`（台账，按当事人/案号/案件简称关键词）→ 判断本案是否已存在。
   - 已有记录 → 沿用记录，更新进展
   - 无记录 → 询问用户确认后建档
3. **案件类型判定**：主诉 / 被诉 / 第三人 / 仲裁 / 执行 / 其他，写入台账字段。
4. **首批期限**：根据诉讼阶段推算——
   - 一审被诉：签收+15 日答辩期 + 30 日举证期
   - 二审被诉：签收+15 日答辩期
   - 主诉：起诉→受理，跟进立案受理书
   - 仲裁：按仲裁规则规定期限
   ——写入台账"到期日"字段；如用户配置了日历集成（`COLLAB.calendar_*`），同步创建日程。
5. **交付**：向用户返回收案摘要 + §0.4 下一步三选一。

### 1.2 收案模板

```
【新收案件登记】
案件简称：{原告}诉{被告}{案由}案
案号：{案号 or 待受理}
法院：{法院}
诉讼阶段：{一审/二审/再审/执行}
案件类型：{主诉/被诉/第三人}
关键期限：
  - {期限类型}：{到期日}
  - ...
建档字段（台账 recordId）：{...}
```

## 2 | 流程推进（9 环节）

案件流程按业务流分 9 环节，AI 主导或辅助执行，每完成一步后按 §0.4 输出三选一。

> 仅预设通用、必要的环节；个性化场景分支由用户按需在 `/customize` 中扩展，本 Hub 不提前预设。

```
收案录案 → 管辖异议 → 还原事实 → 制定策略 → 证据调取 → 文书撰写 → 主诉立案 → 开庭 → 判决履行
```

### 2.1 环节责任矩阵

| 环节 | AI 责任 | 人工必要项 | 衔接技能 |
|------|---------|-----------|---------|
| 收案录案 | 短信/邮件解析 + 建档 + 首批期限 | 归属确认 | §1 |
| 管辖异议（仅被诉考虑）| 草拟异议书 | 提交 | `/procedural-documents` |
| 还原事实 | 事实梳理 | 定位人员、面谈 | `/case-facts` |
| 制定策略 | 攻防分析 + 法律研究 | 决策 | `/element-analysis` + `/legal-research` |
| 证据调取 | 组证清单 + 目录 | 公证/银行调证 | `/evidence-index` + `/evidence-binder` |
| 文书撰写 | 草拟文书 | 审核修改 | `/defense-statement` / `/plaintiff-complaint` / `/agency-opinion` / `/cross-examination` 等 |
| 主诉立案 | 材料清单 | 网上立案/递交 | — |
| 开庭 | 庭审提纲 + 庭后代理词 | 出庭 | `/trial-outline`；`/agency-opinion` |
| 判决履行 | 履行清单 + 强执申请书 | 递交 | `/procedural-documents` |

### 2.2 环节完成后的回写与三选一

每个环节完成后：
1. 按 §0.7 更新台账"案件进展"字段
2. 更新"下一步动作"字段为下一环节的默认动作
3. 按 §0.4 输出「下一步三选一」

## 3 | 台账引擎

### 3.1 建档字段（默认模板，用户可在 profile.md 覆写）

台账建议字段（语义化命名，实际列 ID 由 `ledger_fields` 映射）：

| 语义字段名 | 内容 |
|-----------|------|
| 案件简称 | 用于快速识别的一句话摘要 |
| 案号 | 法院案号或立案编号 |
| 当事人 | 原告/被告/第三人 |
| 法院 | 立案/受理法院 |
| 案由 | 民事案由分类 |
| 诉讼阶段 | 一审/二审/再审/执行 |
| 案件类型 | 主诉/被诉/第三人/仲裁/执行 |
| 阶段进度 | 收案/答辩/举证/开庭/判决/履行/结案 |
| 案件进展 | 追加式，含日期戳 |
| 下一步动作 | 一句话，AI 默认执行前提示 |
| 关键期限 | 答辩期/举证期/上诉期/申请再审期/申请执行期 |
| 开庭日期 | ISO 8601 |
| 结案状态 | 在办/已结案/已执行 |

> 用户可在冷启动访谈中自定义扩展字段（如外部律师信息、预算、利益冲突等），以上为最小通用集合。

### 3.2 建档

```
COLLAB.sheet_create_record(sheet=ledger, fields={...})
```

字段完成度不足时按 `[待补]` 占位。降级模式写入本地 `litigation-portfolio.json` + `matters/<slug>/matter.md`。

### 3.3 跟进

```
1. keyword 搜索 recordId
2. 读取当前"案件进展"值
3. 追加新条目（日期戳 + 简报）
4. 更新"下一步动作"
5. COLLAB.sheet_update_record 写入
```

### 3.4 阶段流转

依据文书类型与法院送达自动推进阶段：

| 文书 | 阶段流转 |
|------|---------|
| 起诉状（提交）| 起诉状提交 → 立案审查 |
| 立案受理书 | 立案审查 → 已受理 |
| 答辩状 | 已受理 → 已答辩 |
| 证据交换记录 | 已答辩 → 举证质证 |
| 开庭传票 | 举证质证 → 开庭 |
| 一审判决书 | 开庭 → 一审判决 |
| 上诉状 | 一审判决 → 二审 |
| 二审判决书 | 二审 → 生效 |
| 履行申请 | 生效 → 履行/执行 |

### 3.5 结案与归档

```
1. 更新"结案状态" = 已结案/已执行
2. 更新"案件进展" 追加 "结案：{结案方式}"
3. 触发 /case-review 建议
```

### 3.6 全景查询与异常检测

```
COLLAB.sheet_query(sheet=ledger, filter="结案状态=在办")
→ 按阶段/开庭日聚合展示
```

**异常检测**（全景查询时自动标注）：
- 🔴 期限已过期未处理
- 🟠 期限 ≤ 3 天临期
- ⚠️ 保全将到期未续封
- ⚠️ 上诉期/执行期临近未决

> 不做决定，只呈现事实与异常。如用户需要定时提醒，可在 `profile.md` 中配置定时任务与提醒渠道。

## 4 | 期限引擎

### 4.1 期限计算（简表）

| 期限类型 | 计算规则 |
|---------|----------|
| 答辩期 | 送达日 + 15 日 |
| 举证期 | 一审 15-30 日 / 二审 15 日（约定优先）|
| 上诉期 | 判决书送达日 + 15 日 |
| 申请再审期 | 判决生效日 + 6 个月 |
| 申请执行期 | 判决生效日起 2 年 |
| 保全续期 | 保全期届满前 7 日申请续封 |
| 管辖异议 | 提交答辩状期限内 |

计算完成后写入台账"关键期限"字段；如用户配置了日历集成（`COLLAB.calendar_*`），同步创建日程提醒。特殊期限（保全续期 / 执行申请期）另加 T-7 提前预警。

> **失权警示**：所有期限输出附"本计算供参考，最终以法院文书载明与承办律师核实为准"。

### 4.2 待办管理

期限计算结果生成待办条目，跨案件聚合，按四档分类展示：

| 标记 | 含义 |
|------|------|
| 🔴 | 已过期 |
| 🟠 | 今日到期 |
| 🟡 | ≤ 7 天 |
| 🟢 | ≤ 30 天 |

## 6 | 执行规则

1. **不越权**：只管案件记录、期限、流程节点和进展跟踪，不起草文书、不做法律分析、不替律师决策。
2. **审计可追溯**：所有更新仅追加"案件进展"，不覆盖历史。
3. **保密**：案件信息 CONFIDENTIAL，不跨案件泄露。
4. **降级透明**：能力槽 provider 缺位时明确标注 `[本地模式-协作平台未连接]`，绝不静默。
5. **最新动作优先**：多通道信息冲突时以时间最晚为准；语义冲突标记待确认。
6. **提醒克制**：默认仅通过对话展示提醒，不主动创建日程——除非用户在冷启动中明确启用日历集成。
7. **下一步三选一**：每个业务环节完成后必须输出 §0.4 格式的三选一表格，AI 默认即时执行 A，无需等待用户回复。
8. **台账规则**：台账用户可读可写，所有案件操作直接读写台账。
9. **日程标题禁用管道符**：会导致 summary 为空，统一用 `-` 或全角 `｜`。
10. **台账自动回写**：任何套件技能产出案件级交付物后，必须在输出文档之前执行 §0.7 台账回写协议——搜索 recordId → 追加进展 → 更新下一步动作 → 写入，不依赖用户手动触发。回写失败不阻塞输出但须标注。
11. **最小干预**：台账字段精简通用，不预设复杂流程，随用户交互自然沉淀。

## 8 | 参考实现建议

```yaml
COLLAB.*:
  ledger:
    provider: COLLAB.sheet
    backend: <your-backend>      # 钉钉 AI 表格 / 飞书多维表格 / 本地 CSV+Sqlite / ...

    案件简称: <col_id>
    案号: <col_id>
    案件进展: <col_id>

    # ...

    provider: COLLAB.calendar
    backend: <your-calendar-backend>
```
