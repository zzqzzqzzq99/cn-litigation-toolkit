# 被诉答辩状（defense-statement）

生成民商事被动防御方答辩文书，覆盖**诉讼程序**（一审答辩状、二审上诉答辩状、再审答辩状）与**仲裁程序**（仲裁答辩状、仲裁反请求答辩状）五种场景。

## 设计原则

> 要件攻防分析已对案件进行了系统论证，答辩状聚焦于**表达**，不重复发挥。
> 答辩状的核心价值是将防御性分析结论转化为结构严谨、层次分明的书面反驳。

## 适用边界

**本skill处理范围**：实体抗辩 + 部分非管辖类程序抗辩（诉讼时效/主体适格/重复起诉/必要共同诉讼遗漏）+ 证据层面反驳。

**不在本skill处理**：
- **管辖权异议** → 使用 `/procedural-documents` 的管辖权异议家族（`references/02-管辖权异议.md`）。管辖异议在程序上需另文提出（答辩期内单独提交《管辖权异议申请书》），与答辩状是两份独立文书，二者不混编。
- 若被告同时主张管辖异议+实体抗辩，先以管辖异议优先处理（人民法院对管辖异议作出裁定前不展开实体审理）；管辖异议被驳回后再启动本skill撰写实体答辩状。

## 前置条件

在调用本技能前，必须确保以下材料已经准备完毕：

| 序号 | 材料 | 说明 |
|------|------|------|
| 1 | 原告起诉状 | 对方提交的起诉状/上诉状/再审申请书/仲裁申请书/仲裁反申请书原文 |
| 2 | 原告证据目录 | 对方提交的证据清单 |
| 3 | 案件事实梳理 | 经整理的时间线与关键事实（我方视角） |
| 4 | 要件攻防分析 | 包含抗辩事由、要件反驳的系统论证 |

如缺少上述材料，应提示用户先完成相应步骤，不得在缺失关键输入的情况下强行生成。

## 工作流程

### 第零步：主体信息自动补充（文书生成前必经）

所有诉讼文书在生成最终稿之前，必须完成主体信息的核实与补充：

1. **企业主体**（公司、合伙企业、非法人组织等）：
   - 调用工商信息能力槽（BIZ.company_info 或同等接口，如企查查MCP `get_company_registration_info`）查询最新工商登记信息
   - 补充字段：企业全称、统一社会信用代码、住所地、法定代表人/负责人
   - 禁止在诉讼文书主体信息中写入：企业类型、成立日期、注册资本、经营范围等工商登记冗余信息
   - 若能力槽不可用，但用户提供的案件材料中包含相关信息，直接从材料提取并补充
   - 若材料中亦无相关信息，主动向用户询问："请提供[企业名称]的统一社会信用代码、住所地、法定代表人信息"
   - **用户明确拒绝提供时，保留"[待用户补充]"占位符，严禁自行编造或填写虚假信息**

2. **自然人主体**：
   - 无MCP可用，仅依赖用户提供的材料或用户补充
   - 从案件材料中提取：姓名、性别、出生日期、身份证号码、住所地/经常居住地
   - 材料中缺失的，主动向用户询问
   - **用户拒绝提供时，保留"[待用户补充]"占位符，严禁编造**

3. **适用文书类型**：
   - 起诉状、答辩状、代理词中的当事人信息部分
   - 证据目录中的主体证据组
   - 程序性文书中的申请人/被申请人信息
   - 案件事实梳理中的主体识别部分

### Step 1: 接收与校验材料

1. 接收用户提供的起诉状、证据目录、事实梳理、攻防分析
2. 检查四项材料的完整性：
   - 原告起诉状是否完整（含诉请和事实理由）
   - 原告证据目录是否包含证据名称与证明对象
   - 案件事实梳理是否有时间线和关键事实
   - 要件攻防分析是否包含防御策略和抗辩论证
3. 如材料不完整，列出缺失项并请用户补充

### Step 2: 识别程序类型与答辩场景

根据以下特征判断答辩场景：

**一审答辩状**（诉讼）：
- 收到一审起诉状，在答辩期内提交
- 当事人称谓：原告/被告（答辩人）
- 答辩期限：收到起诉状副本之日起15日内

**二审答辩状（上诉答辩）**（诉讼）：
- 对方提起上诉，我方作为被上诉人答辩
- 当事人称谓：上诉人/被上诉人（答辩人）
- 核心任务：维护一审判决正确性
- 答辩期限：收到上诉状副本之日起15日内

**再审答辩状**（诉讼）：
- 对方申请再审，我方作为被申请人答辩
- 当事人称谓：再审申请人/被申请人（答辩人）
- 核心任务：论证不符合再审法定事由

**仲裁答辩状**（仲裁）：
- 收到仲裁申请书，在仲裁规则规定的答辩期限内提交
- 当事人称谓：申请人/答辩人（被申请人）
- 致送：仲裁委员会（非法院）
- 开头引述案件编号："就××××仲裁委员会编号××××的案件中，对于申请人……提出的仲裁请求，现提出答辩意见如下"
- 可一并提出仲裁协议无效、仲裁庭无管辖权、仲裁员回避等程序抗辩
- 答辩书副本份数按对方当事人人数提交

**仲裁反请求答辩状**（仲裁）：
- 对方提出仲裁反请求，我方作为被反申请人答辩
- 当事人称谓：反申请人/答辩人（被反申请人）
- 开头引述："就……对于反申请人……提出的反请求事项，现提出反请求答辩意见如下"
- 致送：同一仲裁委员会

### Step 3: 构建实体防御体系（双层结构）

答辩状采用双层防御结构（管辖异议不在此处处理，见"适用边界"）：

#### 第一层：非管辖类程序性抗辩

> 注意：管辖权异议**不在**本skill处理。如有管辖异议，请使用 `/procedural-documents`（管辖权异议家族）单独出具《管辖权异议申请书》。

仅在涉及以下非管辖程序事项时纳入答辩状：
- 诉讼时效届满（属实体性抗辩，但通常前置主张以避免程序拖累）
- 除斥期间届满
- 原告主体不适格 / 被告主体不适格
- 重复起诉（"一事不再理"）
- 遗漏必要共同诉讼参加人
- 仲裁条款排除诉讼管辖（以仲裁协议为由的不予受理抗辩，与管辖异议有交叉，但其法律效果是诉讼路径整体不当，可在答辩状中作为前置抗辩主张；同时建议另行提交管辖异议）

#### 第二层：实体性抗辩（核心）

从要件攻防分析中提取实体防御要点：
- 请求权基础不成立（法律适用错误）
- 构成要件不满足（逐要件反驳）
- 抗辩权成立（同时履行抗辩、先诉抗辩、不安抗辩等）
- 权利消灭事由（清偿、抵销、免除、混同、合同解除）
- 权利障碍事由（合同不成立、无效、可撤销）
- 免责事由（不可抗力、正当防卫、紧急避险）

#### 第三层：证据层面反驳

针对原告证据进行系统反驳：
- 证据真实性质疑
- 证据关联性否认
- 证据合法性挑战
- 证明力不足的论证
- 我方反证的提出

### Step 4: 撰写答辩状

> 📎 **模板单一权威源**：`references/templates.md`（覆盖一审答辩/二审上诉答辩/再审答辩/仲裁答辩/仲裁反请求答辩五种骨架 + 填写指引）。SKILL.md 不再内嵌骨架，仅保留场景差异化提示与硬性铁律。

#### 4.1 场景 → 模板映射

| 答辩场景 | templates.md 章节 | 特别要求 |
|---------|-----------------|---------|
| 一审答辩状 | §一 | 15 日内提交；称谓答辩人（被告） |
| 二审上诉答辩状 | §二 | 15 日内提交；称谓被上诉人；核心任务=维护一审判决正确性 |
| 再审答辩状 | §三 | 核心任务=论证不符合《民诉法》第 211 条法定事由 |
| 仲裁答辩状 | §四 | 案号引述在开头；可并列程序抗辩（协议无效/庭无管辖/回避）；副本按对方当事人人数交 |
| 仲裁反请求答辩状 | §五 | 与本请求同一仲裁委；称谓答辩人（被反申请人 / 本案申请人） |

#### 4.2 答辩点写作三段式（统一框架）

每个答辩点固定"**回应 + 辩驳 + 结论**"三步：
1. 回应：客观转述对方主张
2. 辩驳：事实层 + 法律层双维度反驳
3. 结论：明确该项主张"不能成立/应予驳回"

**排列顺序**：非管辖类程序抗辩（时效 / 主体 / 一事不再理）→ 实体抗辩（按对方诉请顺序）→ 证据反驳 → 总结。管辖权异议**不写入本状**（走 `/procedural-documents`）。

#### 4.3 落款铁律（强制）

> ⚠ **禁止使用任何 HTML 标签**（`<div>`、`&nbsp;`、`<br>`、`<p align>` 等）。Word 转换脚本（`scripts/md2docx_legal.py`）会将 HTML 标签当文本输出导致乱码。右对齐效果由 Word 模板段落格式控制，Markdown 侧仅写纯文本。

### Step 5: 输出文档（md 优先）

> **⛔ 交付前必过闸门**（见 Expert.md「共享护栏」）：核验对象为答辩状全文。

**默认交付 Markdown**：核验放行后先产出 md 成品（写入输出目录并回链），随后询问用户「是否转 Word（Word 转换后端（DOCX.md_to_docx））」，确认才转 .docx。

> **🔗 台账自动回写（强制）**：在产出 md 成品之前，调用「案件管家」§0.7 自动同步接口：搜索台账 recordId → 追加案件进展（"{日期}答辩状已起草（主要抗辩：{1句}）"）→ 更新下一步动作 → 写入。搜索无结果跳过回写并标注；回写失败不阻塞输出但标注"⚠️ 台账未自动更新"。

> **输出文件命名**：`{案件简称}_答辩状_{日期}.md`（二审为 `_上诉答辩状_`，再审为 `_再审答辩状_`）。Word 版同名 `.docx`。

#### 转 Word 排版规范

> **🔒 Word 排版铁律（强制）**：所有诉讼文书转 Word 时，**必须**使用 `scripts/md2docx_legal.py` 转换脚本（路径：`${SUITE_ROOT}/scripts/md2docx_legal.py`），用法：`python3 md2docx_legal.py input.md output.docx`。该脚本严格按照最高人民法院诉讼文书样式模版执行排版：宋体、标题二号居中不加粗、正文四号首行缩进2字符、行距固定25磅、此致缩进+法院顶格+签名右对齐+附件缩进。**禁止**使用 pandoc 或其他工具直接转换（格式不达标）。排版铁律全文见 `format-spec.md`。

> 排版参数详见 Expert.md「核心参数速查」（源：format-spec.md）。

## 答辩策略选择指南

根据案件实际情况，选择合适的答辩策略组合：

| 案件态势 | 推荐策略 |
|----------|----------|
| 涉及管辖瑕疵 | **不写入答辩状**，单独走 `/procedural-documents`（管辖权异议家族） |
| 程序有非管辖类瑕疵（时效/主体等） | 优先非管辖程序抗辩，实体答辩备选 |
| 实体权利明显不成立 | 聚焦要件不满足的论证 |
| 事实有争议 | 强化证据反驳，动摇对方举证 |
| 综合防御 | 程序+实体+证据三层全面展开 |
| 部分承认部分否认 | 明确承认范围，集中火力反驳争议部分 |

## 质量检查清单

生成答辩状后，自查以下要点：

- [ ] 诉讼阶段判断是否正确（一审/二审/再审答辩）
- [ ] 当事人称谓是否与诉讼阶段匹配
- [ ] 是否逐项回应了对方的诉讼请求/上诉请求
- [ ] 每一答辩点是否遵循"回应+辩驳+结论"结构
- [ ] **未将管辖异议混入答辩状**（如有管辖异议应另案提交）
- [ ] 双层防御体系（程序非管辖类 + 实体 + 证据反驳）是否合理运用
- [ ] 法条引用是否完整且格式正确
- [ ] 答辩结论是否明确（驳回诉请/驳回上诉/驳回再审）
- [ ] 二审答辩是否围绕维护一审判决正确性展开
- [ ] 再审答辩是否针对法定事由逐项反驳
- [ ] 排版是否符合规范要求

## 注意事项

1. **不重复分析**：答辩状应当是攻防分析结论的"表达层"，避免展开过于详细的新论证
2. **回应全面**：对方的每项诉请/上诉理由都应有对应回应，不可遗漏
3. **语言风格**：正式、精炼、逻辑清晰，反驳有力但不带情绪化表达
4. **策略性沉默**：对于无需反驳或反驳可能暴露弱点的问题，可选择不正面回应
5. **留白策略**：先尝试通过 MCP 自动填充（工商信息后端查职务、案件管家查法院/案号），仅在后端均不可用时才使用 `[待填写]` 占位并提示用户补充
6. **避免自认**：答辩中注意不要无意中承认对己不利的事实

## 下一步建议

答辩状完成后，根据案件进展可继续：
- **证据质证** → `/cross-examination` 对原告证据逐项出具三性意见
- **举证准备** → `/evidence-index` 编排被告方证据清单
- **庭审准备** → `/trial-outline` 生成庭审应对预案和法庭询问清单
- **管辖异议** → 如需提管辖异议，使用 `/procedural-documents`（答辩期内独立提交）

## Verification

生成完成后确认：
1. 文档结构完整（标题至落款无遗漏）
2. 诉讼阶段与答辩类型匹配
3. 核心论证来源于要件攻防分析（非凭空发挥）
